# Import / Export capability

Status: in progress. Optional (`defaultInstalled: false`); the root reference enables the personal Projects example. Evaluation: [IMPORT_EXPORT_MODULE_EVALUATION.md](../../IMPORT_EXPORT_MODULE_EVALUATION.md).

## Requirements and ownership

Hard capability requirements: Jobs and Object Storage. Baseline: PostgreSQL18, Drizzle, Node24; Authentication is application composition. Notifications and Audit Log are optional application-owned adapters, never imported into the independent capability. One application-owned typed registry declares at most64 definitions. Definition names match `[a-z][a-z0-9]*(?:[.-][a-z0-9]+)*`, maximum64; versions are bounded strings. Each definition supplies exact ordered columns, authoritative Zod schema, current scope authorization, transactional import and stable-key snapshot export callbacks. Unknown definitions fail invalid-input. Callbacks are trusted application code, must honor the supplied signal, and must not perform irreversible external I/O or independent commits.

## Cross-framework v1 contract

Trusted context contains `requesterId` and exact `{kind:'user'|'tenant',id}` scope. Identity IDs are nonempty opaque strings, maximum128 UTF16 code units, without controls; user scope must equal requester. Tenant selection is never authority. The application authenticates and verifies scope before constructing context; worker authorization resolves current permission from persisted requester/scope. Transfer UUIDs and UTC timestamps belong to the capability.

`createTransfers` injects one application DB, registry, lazy Storage accessor, transaction-aware Jobs enqueue, supported Jobs lookup/cancel and optional same-transaction completion hook. `stageImport` authorizes, allocates a generated private source key/receipt, consumes bounded bytes, computes SHA256/length, uploads once and HEAD verifies length; its receipt and S3 PUT are separate operations. `startImport` owns a short transaction setting staged to pending and recording the exact queue/job ID; `requestExport` atomically creates pending receipt and enqueues only `{transferId}`. Caller idempotency keys are printable ASCII1–128, scoped by requester/scope/direction; fingerprints include definition/version and import receipt/source identity. Identical replay returns the existing receipt; changed request conflicts. There is no write retry after ambiguous connection loss.

States: uploading → staged → pending → succeeded/failed/cancelled. Pending includes queued/running; startedAt is descriptive, not a lease. `getTransfer` and newest-first `listTransfers` enforce exact requester/scope visibility; foreign resources return generic not-found. Summaries exclude object pointers, URLs, rows and job payloads. Lists default25, accept integer1–100 and canonical unpadded base64url `[1,createdAtISO,id]` cursor, maximum2048 characters, reapplying scope on every page. No cursor authorizes access.

`cancelTransfer` persists cancellation under the receipt lock before best-effort native Jobs cancellation. A committed success conflicts; cancellation never reverses domain data. A running locked import can win first. `getExportDownload` checks current permission, success and expiry before GET presigning for `min(600,remainingLifetime)`; under30 seconds is expired. Already issued bearer URLs can remain usable until expiry after revocation. Expiry denies access without physical deletion.

`reconcileTransfer` and bounded `reconcileTransfers` lock receipts and inspect only their recorded native queue/id through supported pg-boss APIs. Terminal receipt success always wins; native failed/cancelled becomes terminal failure/cancelled; missing native job becomes execution-lost. Active/retry/created are not failed based on elapsed time. Explicit operator command: `bun run import-export:operator -- reconcile <ids>`. Status refresh invokes reconciliation; no daemon is added.

`purgeTransferArtifacts(ids)` defaults dry-run, bounded100 selected receipts, terminal or expired abandoned uploading/staged only. Execute requires `bun run import-export:operator -- purge <ids> --execute`. It retains receipts, domain data and migrations; deletes only generated pointers recorded in selected receipts, including unpublished attempt output keys. No prefix deletion, startup cleanup or scheduled retention.

All bounded input validates before domain mutations. Import callback runs once per committed receipt under a row lock with fresh permission and deadline/state checks; callback domain writes and succeeded receipt share one Drizzle transaction. Concurrent stale attempts can parse but cannot apply a terminal receipt. This is one committed application, not exactly-once execution or business deduplication across transfers. Export uses one bounded read-only REPEATABLE READ transaction, stable application ordering and records snapshot time; successful attempt snapshot is not request time. After closing it, output uploads to a fresh generated key. A final row lock/current-permission/deadline check publishes pointer plus success. No download for partial output; retries may use a newer snapshot.

Attempt timeout includes configuration, resolution, body acquisition/transfer, validation, database and publication. Storage signal reaches SDK GET/PUT/HEAD and GET body destruction. PostgreSQL transaction_timeout/statement_timeout are at most min(30s,remaining budget), lock_timeout at most5s. No database transaction waits for S3/provider transfer. Native queue policy:5 retries, initial30s, exponential backoff/native jitter, maximum900s, expiry timeout+30s, retention86400s. Only timeout/unavailable are advisory retryable. Known final native metadata permits final catch persistence; shutdown/claim abort does not imply terminal failure. Reconciliation handles hard crashes.

## CSV format and limits

Server-only pins `csv-parse:7.0.3`, `csv-stringify:6.9.0`; no umbrella/browser parser. UTF8 fatal decoding; optional BOM. Comma, double quotes/escaped quotes, LF/CRLF and quoted multiline. Mandatory exact ordered header; no duplicate, missing, unknown or prototype-related names. Rows parse as arrays before safe-object mapping. No dialect guessing, compression, workbooks, remote URLs, filename persistence, parser trimming or automatic type conversion. Empty data record invalid; one final terminator normal; header-only import succeeds with0 rows.

Fixed limits:64 columns; header64 UTF16 code units; field65536 UTF8 bytes; logical row262144 UTF8 bytes; normalized JSON at most twice max bytes;100 safe issues then errorsTruncated. Issues contain logical row ordinal(first data row1), registered field if available and closed invalid-value code, never cells/parser messages. Byte buffering is bounded and field/record/column checks precede parser allocation.

Exports registered order/header, CRLF/final CRLF, no BOM. Null/undefined empty, booleans true/false, finite numbers JS String; objects/arrays/nonfinite unsupported. Dates require explicit application ISO string formatting. Canonical string escaping prepends one apostrophe for leading =,+,-,@,TAB,CR,LF/fullwidth variants or whitespace then =,+,-,@/fullwidth variants; numeric negatives remain numeric. CSV deliberately changes dangerous strings and is not a lossless arbitrary-data backup. No mitigation guarantees every spreadsheet configuration is safe.

Server-only lazy settings: `IMPORT_EXPORT_MAX_BYTES` default16777216, integer1024–67108864; `IMPORT_EXPORT_MAX_ROWS` default10000,1–100000; `IMPORT_EXPORT_TIMEOUT_SECONDS` default60,5–300; `IMPORT_EXPORT_ARTIFACT_TTL_SECONDS` default86400,300–604800. Undefined/empty defaults; decimal digits only, no exponent/parseInt syntax. Existing DATABASE_URL/Jobs/Storage meanings remain. Missing S3 does not break build/start/health. TTL starts when staging/publication finishes; expired source cannot start/apply.

Safe static `{code,message,retryable}` errors: configuration,invalid-input,unauthenticated,forbidden,not-found,conflict,limit-exceeded,invalid-format,validation-failed,expired,cancelled,timeout,unavailable,execution-lost,unsupported,unknown. No raw causes, SQL, secrets, session objects, source cells, names, keys, URLs or environment values in default logs. Start transports return safe unions; upload HTTP statuses follow the documented outcome codes.

## Reference example

Personal Projects CSV is exactly `name,description`; existing trimmed name1–120/description0–1000 validator owns semantics, empty description null. Import creates fresh IDs/current owner, never accepts IDs or changes existing Projects. Export selects only personal owner Projects ordered createdAt ASC,id ASC. Reimport creates additional Projects: content round-trip, not restoration. Optional Audit composition belongs to the application. Native Start `/app/transfers` supports stage/start/status/safe issues/cancel/download and `/api/transfers-stage` accepts application-controlled bytes without browser key/scope/path/URL.

## Installation, migration and removal

Compile official source with `bun run add-ons:compile import-export`; generic catalog discovery supplies Jobs/Storage closure and official Drizzle integration. Independent assets provide an empty application registry to customize, never import unrelated capabilities. Overlay of the Jobs registry and drizzle.config is reviewed for the clean baseline only; customized consumers must manually preserve existing handlers/schema, not rely on generic semantic merging. Explicit application migration and Jobs migration are release prerequisites; no import/build/app/worker startup schema mutation.

Stop producers and drain or preserve pending work before removing handler/routes/UI/config/scripts/CSV packages. Retain Jobs/Storage and their packages/data, transfer schema declarations/tables, applied SQL/journal and objects. Explicit operator artifact purge is separate. Keep reusable authoring source separately if desired. See [removal recipe](../../docs/STARTING-A-PROJECT.md#remove-import-export).
