# PWA / Offline v1

Status: in progress, pending exact-head hosted native browser/lifecycle/full CI. Root reference wiring is prepared at `/pwa-test`; no completion claim. Independently opt-in (`defaultInstalled: false`), no hard capability dependencies. Notifications and Realtime are optional future integrations, not installed or used by v1.

## Scope and threat model

This is an installability/lifecycle primitive and an inert public offline notice, **not** a local-first app or an offline account session. No background sync, mutation queue, push, user-data storage, account snapshots or persistence are implemented. Only three fixed capability-owned files are precached: the inert HTML notice and two content-fingerprinted PNG icons. All app JS/CSS, SSR documents, navigation responses, APIs, auth/callbacks, uploads, dynamic content, errors and third-party URLs are excluded. Files merely placed in `public` are never discovered. Native `vite-plugin-pwa` 1.3.0 `injectManifest` uses Workbox build 7.4.1 with empty globs, automatic registration disabled, icon auto-inclusion disabled, and a transform returning the fixed allowlist. The plugin's automatic manifest entry is explicitly cleared; the web manifest is public but not cached by this worker.

SHA-256 integrity is computed from these three build-reviewed files and passed to each Fetch request with `credentials: omit`, `redirect: error`, `cache: no-store`. SRI rejects changed bytes before a cache write. New install fetches share a 15-second abort deadline. Each response must additionally be basic, exact same-origin URL, status 200, not redirected, public and not private/no-store/no-cache, with only absent/Accept-Encoding Vary and a fail-closed unquoted Cache-Control directive grammar, and exact expected HTML/PNG MIME. PNG responses must be immutable. Content-fingerprinted filenames must be updated when icon bytes change. A failed install removes only a newly created versioned partial cache. An already-existing complete same-version cache must pass exact URL-count, response-header and SHA-256 checks, and is reused without any writes. Existing incomplete or invalid caches fail closed without deletion. This protects an active worker when emitted bytes change without a content-version change. Worker/policy/config/assets/build-helper/toolchain identity contribute to cache versioning; activation cleans only the prefix containing this exact origin and scope.

This defends against accidental personalized responses and storage of returned private bytes; it is not an XSS defense. Same-origin compromised scripts, compromised build sources or an administrator changing the reviewed allowlist are trusted-origin compromise. Other application code, HTTP cache and preexisting workers are outside this module's storage guarantee. Cookies, Set-Cookie side effects or third-party browser storage policy are not claimed to be erased by logout. The worker itself never reads or stores a session. Cache eviction, private browsing, platform support, device installation and delayed update checks remain browser-controlled.

## Installation and native build

The official custom add-on ships source, fixed public files, build helper, docs and verification scripts. It does not silently rewrite a consumer's Vite config or routes. Import `pwaOffline` from `scripts/pwa-vite.ts` and add `...pwaOffline()` after any Nitro plugin. The adapter limits native PWA hooks to the client environment and resolves its actual output directory before compilation (`dist/client` for standalone Start, `.output/public` with root Nitro). Generation happens before Nitro indexes public assets; there is no late-copy substitute. Production HTTP tests enforce that the real output URL serves the worker with JavaScript MIME. No SSR HTML transform, auto-registration script, local worker dev mode or universal shell fallback is used.

`src/integrations/pwa-offline/config.ts` owns `base`, `publicOfflinePaths` and `retired`. Base must exactly equal Vite's base and be a slash-terminated simple local path. Worker URL is `<base>pwa-offline-sw.js`, scope and manifest ID are that same base, and cache ownership includes the entire registration scope URL. The consumer default fallback list is empty. Only root and isolated test fixtures explicitly opt in `pwa-test`. Public paths are exact relative paths, excluding queries and reserved private prefixes; a product owner must independently confirm that any newly opted-in path is genuinely public. Only a thrown network failure triggers the notice; 401/403/404/500/503 responses remain real responses. No SSR/navigation response is ever written to Cache Storage.

Render `PwaPanel` on an application-owned route and include a manifest link to `<base>manifest.webmanifest` in its head. Set public offline HTML headers to `Cache-Control: public, max-age=300`, HTML UTF-8 MIME; set the two fingerprinted PNG paths to `public, max-age=31536000, immutable`, PNG MIME. Root Nitro route rules do this for only the owned files. Worker JS and manifest must be served at the exact base URL, with JS/webmanifest MIME and no authenticated redirects; use revalidation/no-store for worker updates. HTTPS or loopback secure contexts are required. There are no secrets, environment variables, database migrations, network providers, runtime server processes, service subscriptions or additional infrastructure.

## Lifecycle, install UX and updates

Registration is explicit, idempotent while pending and refuses any overlapping registration with another script URL or scope; it never replaces an unrelated worker. Listeners are installed once per live subscription and detached after the last subscriber. All SSR action buttons are disabled until hydration. `beforeinstallprompt` is retained only when browser-trusted, and `prompt()` is invoked only from the Install button gesture. Synthetic events cannot claim eligibility. Prompt acceptance is described as a request, not completed installation. Only the browser `appinstalled` event claims browser-reported installation; unsupported browsers retain an explanatory disabled control and may provide their own menu.

No `skipWaiting`, `clientsClaim`, forced reload, navigation or immediate activation is used, including retirement. An existing waiting worker activates naturally after all old controlled tabs close. “Later” dismisses the notice; unsaved application forms stay untouched. First installation does not seize an existing tab: the next normal navigation may become controlled. Checking updates is explicit and preserves the current view on failure. Install cancellation or unsupported install APIs do not block ordinary online navigation.

## Two-phase removal: required deployment contract

Removing the source or unregistering one browser is not a production retirement. First set `retired: true`, keep the SAME worker URL, scope and ownership namespace, build and deploy that retirement worker. Stop exposing registration/install UI and the manifest. The retirement worker installs without fetching assets; when old tabs naturally close it removes only its own exact-scope caches and unregisters itself. It never navigates clients or deletes unrelated caches. Retain the retirement script at its original URL for returning clients; offline/dormant devices cannot be certified retired by a server deploy or a finite observation window. Changing filename, base or scope strands old registrations and needs separate retirement of each historical identity.

Only after deploying the retirement artifact and verifying active clients should phase two remove component imports/routes, the build helper, feature source/public icons/HTML, PWA dependencies when otherwise unused, and package scripts. Preserve the exact retirement script at `public/pwa-offline-sw.js` (or the original base's deployment path) through all later builds and releases. Retain it as long as old clients may return. Keep reusable authoring source if reinstalling later is desired; do not mistake deletion of authoring source for runtime removal. Unrelated service workers and cache namespaces are never touched.

The generic clean fixture first runs actual Chromium native update/retirement against an isolated production build. It records a fixture-only SHA-256 receipt and retains the exact retirement worker; guarded `pwa-remove.ts` refuses removal without this receipt. The final lean build verifies that the same tombstone survives after imports/dependencies/source are removed. That receipt proves only the disposable test clients, never real deployments. Application operators must execute both deployment phases themselves. No database data/history exist to remove.

## Verification and limits

`pwa:unit`: URL/base/response/privacy policy, default empty fallback, unsupported/synthetic install, idempotent registration and conflicting ownership; bundled worker VM regressions for same-version no-write cache reuse, failed late-resource updates, incomplete-cache preservation and owned retirement. VM tests supplement native browser proof.
`pwa:packaging`: official no-install blank scaffold retains every asset/import and binary bytes.
`pwa:browser`: actual Vite production injectManifest worker in Chromium; credential omission, integrity/private-header refusal, public offline only, login/logout API isolation, HTTP errors, listener remount, genuine browser eligibility gate, Later/unsaved draft/multiple tabs and natural update, owned-cache-only retirement. This uses a disposable synthetic cookie fixture; root E2E additionally exercises the real Start/Nitro production artifact. Device-specific OS installation/manual browser menus are not automated acceptance claims.
`add-ons:test pwa-offline`: official install, unit/types/browser, actual generated Start production HTTP/browser registration/default-empty fallback, byte-distinct same-version update, failed-new-version late-resource cache preservation, native retirement, guarded removal and final lean HTTP rebuild with persistent retirement artifact. The disposable Node deployment adapter explicitly serves the documented public headers and actual generated Start SSR handler. Root E2E covers SSR disabled controls, hydrated UI, exact worker serving and public-only offline behavior. Full inherited CI remains required. Browser-unavailable local builds never count as browser acceptance.
