# Rich Text / Tiptap capability

Status: in-progress; reference integrated for acceptance, opt-in (`defaultInstalled: false`). No hard capability dependencies, services, credentials, environment variables or migrations.

## Frozen v1 contract

Tiptap React, ProseMirror bridge and Starter Kit are pinned together at stable 3.31.4. `src/integrations/rich-text/document.ts` is the server-safe validation boundary. `RichTextContent` renders validated JSON as escaped React elements; it never executes HTML. `RichTextEditor` renders that same fallback on the server and first hydration pass, then imports `editor.client.tsx` only after mount. Do not import the client entry into server execution. Tiptap also uses `immediatelyRender: false`.

Documents contain one `doc` with one or more paragraphs, headings (levels 1–3), blockquotes, bullet/ordered lists, or code blocks. List items start with a paragraph; inline text supports bold, italic, strike, code and links. Hard breaks are supported in paragraphs/headings. Inline code is exclusive of other marks; mark order is canonicalized. Ordered lists allow a start from 1 to 1,000,000. Unknown nodes, marks, attributes, malformed nesting, accessors, cyclic input and extra properties are rejected. Text CRLF/CR is canonicalized to LF before rendering or persistence; NUL and unpaired surrogates are rejected in both text and links. Valid Unicode, including literal U+FFFD and paired surrogate code points, is preserved. Character limits count the raw input before normalization. Limits: 2,000 nodes, depth 24, 100,000 text characters and 262,144 serialized UTF-8 bytes. Treat the exported empty document as a value, never mutate it. Call `parseRichTextDocument` again at the application's persistence boundary; client validation is not authorization.

Links require absolute HTTP, HTTPS or mailto URLs with no credentials, whitespace or control characters, maximum 2,048 characters. Rendering uses `noopener noreferrer nofollow`; editor links do not navigate on click. No HTML string API, executable nodes, images, embeds or remote assets. Clipboard input is plain text only; HTML formatting, file paste and drop are intentionally unsupported. Paste and transaction output are bounded, and HTML-looking text stays literal. Clipboard line endings are normalized before insertion; invalid scalar clipboard data and any noncanonical CR-containing low-level editor transaction are rejected without storing that input in history.

## Controlled editing and ownership

`RichTextEditor({documentKey, value, onChange, label, readOnly?})` is controlled. Supply an accessible nonempty label and a required nonempty `documentKey` identifying the current record/editing session. Missing or empty identity fails closed. Keep the key stable for accepted updates, including caller-cloned echoes. Change it when switching records or intentionally resetting/reloading a session, even if the next record has identical JSON. The keyed client editor is destroyed/recreated, so no old selection or undo/redo history crosses that identity boundary. Commit a proposed document to React state in the callback to accept it; retain the prior value to reject it. Reconciliation occurs on the transaction's React render, even if the parent does not render. Do not defer the local state commit pending persistence: update local state synchronously, persist separately, then supply an explicit replacement if needed. Persistence, authorization, dirty/pending/error state, conflict handling and cancellation belong to the caller. The synchronous change callback should not throw; handle persistence failures separately.

Accepted edits keep native undo/redo. Rejected edits, external document replacements, unmount/remount and entering/leaving read-only mode reset undo/redo, preventing prior document content from reappearing. A changed canonical JSON value within the same key also resets history. Identical JSON under an unchanged key is the same editing session, not a record switch; record/revision identity must be expressed by changing `documentKey`. Replacing the document resets the selection. Safe toolbar groups have native keyboard-operable buttons with formatting pressed states; link input has its own label and validation feedback. The toolbar provides H2; H1/H3 documents remain supported. The module does not manage keyboard shortcuts outside the editor.

No Yjs/collaboration, uploads, autosave, beta Markdown bridge, paid extensions or provider integration in v1. Storage, Markdown, Realtime and Organizations integrations are optional future application composition.

## Install and removal

Install `capabilities/rich-text/add-on.json` using the official TanStack CLI. Runtime dependencies are the three matching Tiptap packages; portable regression tooling adds Playwright and Bun types as development dependencies. The clean consumer uses normal Vite dependency discovery. An application that opts into `optimizeDeps.noDiscovery` must include `@tiptap/react`, `@tiptap/starter-kit` and `@tiptap/pm/state` in its client dependency configuration, as this reference does.

Remove application imports and `src/integrations/rich-text`, demonstration routes, portable `scripts/rich-text-*` fixtures and the `rich-text:browser` script; remove the three Tiptap dependencies and unused explicit Vite entries. Remove Playwright/Bun types only if no other tools need them. Delete installed `capabilities/rich-text/CAPABILITY.md`, then reinstall, typecheck and rebuild. CLI provides no uninstall transaction. Reusable add-on authoring source is separate and can be retained. No stored documents or database history are deleted. The removal script guards its own disposable consumer name and is not a production uninstaller.

## Verification

Root `rich-text:unit` exercises strict schema/security, escaped SSR/hydration and actual Tiptap controlled interactions. `rich-text:typecheck` checks authored assets. `rich-text:browser` executes real Chromium against server-rendered markup and its hydrated actual editor; `e2e/rich-text.e2e.ts` runs the same interactions on the native Start reference route in development and production. `add-ons:test rich-text` compiles freshness, independently installs, typechecks, executes real-browser interactions, builds, removes, typechecks and rebuilds. Local OS socket policy blocks Chromium and Nitro worker Unix sockets; blocked stages must run in hosted CI, not be skipped in acceptance. Capability stays in-progress until the exact published head has passed complete CI.
