# Webhooks module evaluation (September 2026)

Decision: implement the Standard Webhooks 1.0.0 HMAC v1 contract directly with Node 24 `createHmac`, `timingSafeEqual`, `randomUUID` and native fetch. No HTTP/signing dependency is needed. Official JS reference is maintained (1.1.1, source updated August 2026); it converts Buffer to text before signing. Direct crypto permits exact arbitrary raw-byte verification and bounded configurable tolerance, retaining compatibility for UTF-8 JSON. Ed25519 is not supported.

Research sources (reviewed September 30):

- [Standard Webhooks specification](https://github.com/standard-webhooks/standard-webhooks/blob/main/spec/standard-webhooks.md), version 1.0.0.
- [Official JS source](https://github.com/standard-webhooks/standard-webhooks/blob/main/libraries/javascript/src/index.ts), [package 1.1.1](https://github.com/standard-webhooks/standard-webhooks/blob/main/libraries/javascript/package.json) and [published signing vector](https://github.com/standard-webhooks/standard-webhooks/blob/main/libraries/javascript/src/webhook.test.ts).
- [Node 24 globals](https://nodejs.org/docs/latest-v24.x/api/globals.html), [crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html) and corresponding official `nodejs/node` `v24.x` docs, researched through GitHub when environment proxy was unavailable. Native fetch is stable/Undici-backed; AbortSignal timeout and Web Crypto are available. Node crypto gives synchronous HMAC and constant-time digest comparison without adopting a pure-JS crypto dependency.
- [pg-boss 12.35.0 jobs](https://github.com/timgit/pg-boss/blob/12.35.0/docs/api/jobs.md), queue docs and installed types/implementation. Native retry/backoff/jitter/max-delay and retry policy is used through Jobs. Throttling/singleton time slots do not provide permanent event replay protection.

Exact message is `id.timestamp.` followed by exact HTTP body bytes, HMAC-SHA256, base64 encoded with `v1,` prefix. Headers are webhook-id/timestamp/signature plus application/json; envelope is stable `{id,type,createdAt,data}`. Published vector with `whsec_MfKQ9r8GKYqrTwjUPD8ILPZIo2LaLaSw`, ID `msg_p5jXN8AQM9LWM0D4loKWxJek`, timestamp 1614265330 and body `{"test": 2432232314}` must yield `v1,g0hM9SsE+OTPJTGt/tmIKtSyZlE3uFJELVlNIOLJ1OE=`. This vector passed locally.

Raw verification checks Content-Length and actual bytes before parsing, verifies exact bytes with constant-time 32-byte comparison, fatal UTF-8 decodes, validates typed registered event data and matches envelope ID to signed ID. Custom validator exceptions are sanitized to the static event category. Explicitly classified safe transient resolver errors can retry; unclassified resolver exceptions never expose their messages. Default 300-second tolerance (1–900), 64 KiB body (up to 1 MiB direct), bounded 10-second read timeout. Rotated previous secrets accepted (up to eight); outbound resolves current primary per attempt. IDs/body never change across retry; attempt timestamp/signature refresh.

Replay/idempotency: signature/tolerance is not replay protection. Durable application-owned `handoffOnce` must atomically couple event-ID storage and typed Jobs enqueue, rollback on failure and namespace trusted sources appropriately. No hidden table/Cache dependency. Every deliberate enqueue may create work. No scheduler-level duplicate suppression is promised; application durable idempotency remains required. Delivery is at least once.

Targets are application-owned references resolved server-side; URL/secrets are absent from job payloads. PostgreSQL necessarily retains event data; minimize payloads and secure retention/backups. HTTPS/default literal safety checks, embedded credentials/fragment rejection, explicit development-only HTTP/private policy, and stronger application URL/DNS/network validation hook. No DNS rebinding protection claim. Native fetch manual redirects; no authorization forwarding. The entire attempt, including resolver/policy/signing/fetch, shares a 10-second deadline (100 ms–30 seconds). Resolver/policy receive an AbortSignal. Remote bodies are never read; status alone determines the result.

Network/timeout and 408/425/429/5xx retry. Other 4xx, redirects and invalid target/configuration/event are permanent. Safe errors expose retryable/category/status only. Permanent delivery result completes the Jobs task with outcome=permanent, preserving terminal facts without pg-boss retries; consumers must distinguish completion from successful delivery. Five default pg-boss retries, exponential jitter from 30 seconds, capped delay 900 seconds, active expiry 60 seconds, one-day completed retention. Retry-After is not acted on; policy can be customized by app. Existing queue updates are explicit, not migrations on startup.

Optional Observability/API/Audit integration is an application adapter; no imports or dependency on another planned branch. Safe registered event-type/outcome/status/duration lifecycle callback isolates failures; no body/signature/secret/URL logging, no tenant identifiers as labels. Inbound domain processing is application-owned typed Jobs; signed callbacks require no API key by default.

Packaging: dependsOn uses actual `postgres-jobs` ID, transitive official Drizzle resolves through CLI. Generic catalog-driven lifecycle serves custom dependencies first and maps custom IDs to local URLs in served copies because CLI 0.71 overwrites remote add-on IDs with URLs; retained metadata always uses postgres-jobs. `bun scripts/add-ons.ts serve webhooks` exposes the same transport for local installation. Direct raw artifact installation needs an upstream identity fix or publication transport adapter; clean fixture rejects unrelated optional add-ons, verifies raw protocol and real HTTP/Jobs then removes Webhooks and retains/builds/smokes Jobs. Publishing requires both immutable add-on artifacts plus a compatible custom-dependency transport/registry. Existing customized registry requires reviewed composition. Removal retains unrelated history and never mutates remote endpoints.

Containerized Node Webhooks smoke passed, followed by standalone worker and healthy application startup. `/api/health` reported production, Node 24.21.0 and database=ok; OpenAPI/docs probes passed with no external webhook receiver or target configured.
